# Product Requirements Document (PRD)

## Проект: Миграция игры RiotGalaxy с CocosSharp на MonoGame

### Введение

**RiotGalaxy** - это 2D космический шутер в стиле Space Invaders/Galaxian, вдохновленный современной игрой Radiant. Игра разработана на движке CocosSharp (Xamarin) и поддерживает платформы Android, iOS и Windows Phone.

**Цель проекта:** Мигрировать игру с движка CocosSharp на MonoGame, полностью сохранив игровую логику, функциональность и контент. MonoGame выбран как более современный и поддерживаемый фреймворк с лучшей кроссплатформенностью.

**Изменения в процессе разработки:**
- Ранее: MS Visual Studio
- Теперь: VSCode или Windsurf под Linux

**Документация MonoGame:**
- https://github.com/MonoGame/MonoGame
- https://docs.monogame.net/


### Основные функции

**Игровая механика:**
- Управление космическим кораблем игрока (touch, клавиатура, геймпад)
- Система оружия: пушка, пулемёт, лазер с различными паттернами стрельбы
- Разнообразные враги: малые (45x45), средние (55x55), большие (60x60), боссы
- AI врагов: полёт по маршрутам, групповое поведение (ульи), поворот к цели
- Система бонусов: выпадающие звездочки, магнит для сбора
- Система уровней с загрузкой из файлов

**Графика и визуал:**
- Пиксельарт стиль (разрешение 1280x768)
- Спрайты юнитов и анимации
- Спецэффекты (взрывы, выстрелы)
- Тайловые карты и задники
- Сплэш-скрины и экраны меню

**Аудио:**
- Звуковые эффекты (выстрелы, взрывы)
- Фоновая музыка (BGM)

**UI:**
- HUD (индикаторы здоровья, очков)
- Система меню и переходов между состояниями игры
- Диалоги и кат-сцены (радиопереговоры с NPC)

**Архитектурные особенности:**
- Иерархия игровых объектов
- Паттерн Стратегия для поведения (движение, стрельба, столкновения)
- Паттерн Команда для управления событиями
- Паттерн Состояние для AI (конечный автомат)
- GameManager для управления игровыми состояниями
- World - матрица игрового поля для движения юнитов

### Технические требования

1. **Стек технологий**
   - Язык программирования - C#
   - Игровой движок - MonoGame (Microsoft.Xna.Framework)
   - Среда разработки - VSCode или Windsurf под Linux
   - UI-фреймворк - ImGui или MonoGame.Extended (вместо CocosSharp UI)

2. **Docker**
   - Сборка должна проходить в отдельном контейнере-сборщике
   - Без установки каких-либо пакетов в хостовой системе
   - Использование Docker Compose для управления несколькими контейнерами при необходимости

3. **Исходный код**
   - Оригинальный проект находится в директории `CocoSharp` - **запрещено вносить изменения**
   - Новый код создаётся в директории `MonoGame`
   - Сохранение оригинального проекта для исторической справки и сравнения

4. **Целевые платформы**
   - Windows
   - Linux
   - macOS
   - Android
   - iOS (опционально)

5. **Требования к производительности**
   - Не менее 90% FPS от оригинальной версии на целевых устройствах
   - Отсутствие задержек при воспроизведении звука
   - Плавная анимация без артефактов


### Архитектура

**Картирование CocosSharp → MonoGame:**

| CocosSharp | MonoGame |
|------------|----------|
| CCScene | Game (Microsoft.Xna.Framework.Game) |
| CCLayer | Screen / GameComponent |
| CCSprite | Sprite (Texture2D + Position) |
| CCNode | GameObject (custom class) |
| CocosSharp UI | ImGui / MonoGame.Extended |
| CCDirector | Game class (Update/Draw loop) |
| CCAction | Animation system (custom) |
| Schedule | GameTime / custom scheduler |

**Структура проекта:**
```
MonoGame/
├── RiotGalaxy.Core/          # Основная игровая логика
│   ├── GameObjects/          # Игровые объекты (Player, Enemy, Bonus)
│   ├── Components/          # Компоненты (Movement, Shooting, Collision)
│   ├── AI/                   # AI системы
│   ├── Managers/             # GameManager, AudioManager, InputManager
│   └── Utils/                # Вспомогательные классы
├── RiotGalaxy.Content/       # Ассеты (спрайты, звуки, шрифты)
├── RiotGalaxy.DesktopGL/     # Desktop версия (Windows/Linux/macOS)
├── RiotGalaxy.Android/       # Android версия
└── RiotGalaxy.iOS/          # iOS версия (опционально)
```

**Ключевые архитектурные решения:**
- Сохранение паттернов проектирования из оригинала (Strategy, Command, State)
- Адаптация иерархии GameObject под MonoGame
- Реализация собственного планировщика (scheduler) вместо CocosSharp Schedule
- Использование Content Pipeline для управления ассетами
- Разделение логики и рендеринга (GameComponent pattern)

### План разработки

**Ключевые задачи**

| № | Задача | Критерий завершения |

| 3 | Перенести систему рендеринга спрайтов, анимаций и тайл‑карт | 100% оригинального контента отображается без артефактов |

| 8 | Обновить документацию и подготовить миграционный гайд | Полная документация проекта и гайд для будущих миграций |

### Риски и ограничения

**Технические риски:**
- **Риск:** Различия в API между CocosSharp и MonoGame могут потребовать существенной переработки некоторых систем
- **Риск:** Возможные проблемы с производительностью при портировании сложных эффектов
- **Риск:** Некоторые функции CocosSharp могут не иметь прямых аналогов в MonoGame и потребуют кастомной реализации

**Ограничения:**
- **Ограничение:** Оригинальный код в директории `CocoSharp` не должен изменяться
- **Ограничение:** Сборка должна выполняться в Docker-контейнере без установки пакетов в хостовую систему
- **Ограничение:** Необходимо сохранить 100% функциональности оригинальной игры

**Митигация рисков:**
- Детальный анализ архитектуры перед началом миграции
- Постепенная миграция с постоянным тестированием каждого компонента
- Создание эталонных тестов для сравнения поведения оригинала и новой версии
- Использование хорошо документированных библиотек MonoGame.Extended для отсутствующего функционала

### Критерии успеха

- Все игровые механики работают идентично оригинальной версии
- Игра собирается и запускается на всех целевых платформах
- Производительность не ниже 90% от оригинала
- CI/CD pipeline автоматически генерирует артефакты для всех платформ
- Полная документация проекта и миграционный гайд

### Заключение

Этот PRD описывает миграцию старого проекта 2D игры RiotGalaxy с движка CocosSharp на движок MonoGame. Основная цель - сохранить всю игровую логику и функциональность при переходе на более современный и поддерживаемый фреймворк с улучшенной кроссплатформенностью.
